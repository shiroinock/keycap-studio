# 3DプレビューとBlender連携

状態：R3Fプレビュー実装済み。Blender連携・RenderScene/AssetManifestの永続形式は計画段階。

## 実装済みのブラウザ描画

- `src/three/profile.ts`：Studio Sculpted v2、mm単位、+Xが右、+Yが上、+Zが手前。19.05mmピッチで共通配列を配置。独自の行別概形でメーカー資料に基づくCADではない。
- 長尺キーは外形幅を指定し、奥行き・ベベルを維持。スペースは凸、他は浅い凹面。
- `src/three/artwork.ts`：SVGと共通のlegendMarkupから4倍解像度の上面画像を生成し、sRGB CanvasTextureとして使用。外部フォント・HDRI・モデルを取得しない。
- 写真カメラ（垂直FOV 32°）と平行投影、照明・マット／サテンを親状態で共有。停止中は描画を休止し、3Dコードは遅延読込。PNGは同じシーンを指定解像度で描画してから画面サイズへ戻す。
- WebGL初期化エラー、コンテキスト喪失、テクスチャ生成エラーは3D領域に限定。2D切替と保存は継続可能。
- 寸法・配置・UV・法線と日本語エスケープは自動テスト。実ブラウザ結果はverification.md。


## R3Fの画質設定

- 上端の二次曲線ベベルを8分割、上面を20リングで構築。長尺キーの直線辺も細分化。円筒状の凹面／スペースの凸面は解析法線を使い、ベベル終端と位置・法線を共有する。
- `studio.ts`のローカル生成ソフトボックスをPMREMに変換し、照明プリセットごとに環境光・反射を生成。外部HDRI・フォント・モデルを取得しない。
- MeshPhysicalMaterial、IOR 1.46、金属度0。マット／サテンは粗さ0.68／0.38。seed固定の128pxグレインを色テクスチャとは別のuv1に貼り、粗さと微細バンプに使用する。実測PBT/ABSの再現ではない。
- 2048pxのPCFシャドウ、独自の解析的なケース下接地影を併用。後者は丸角矩形の距離に応じた減衰で、SSAOやレイトレースではない。
- 通常照明はACESFilmic、露出0.9、色テクスチャsRGB。低い視点では背景へフォグでつなぐ。PNGと画面で同じ色管理を使用。
- 比較案は同じ投影方式・位置・ズーム・照明を共有。テクスチャと環境マップは各Canvas内で生成し、アンマウント時に破棄。停止中はdemand描画でGPU処理を休止する。
- コードはThree.js標準機能と公式addonsを利用。追加npm依存なし。 [PMREMGenerator](https://threejs.org/docs/pages/PMREMGenerator.html) / [MeshStandardMaterial](https://threejs.org/docs/pages/MeshStandardMaterial.html)

## 役割

| 出力 | 目的 | 実行方法 |
| --- | --- | --- |
| SVG | 配列、文字、配色の正確な編集・確認 | ブラウザ |
| React Three Fiber / Three.js | 回転・拡大できる3D、配色の即時確認 | ブラウザ |
| Blender / Cycles | 質感・陰影を含むフォトリアルな商品イメージ | まずローカルCLI |

R3FはThree.jsのReactレンダラーであり、Blenderの実行環境ではない。両者は同じデザイン・形状資産を利用する別の描画経路として設計する。

## 共通データと資産

- **ResolvedKey**：安定したキーID、位置、寸法、回転、解決済み色・レジェンド・Novelty。2D/3Dで割り当てを二重実装しない。
- **KeycapProfile**：プロファイルIDと資産版、行別の形状、幅別の形状、UV、原点・向き。長尺キーは1uの単純な横伸ばしで代用しない。
- **RenderScene**：schemaVersion、デザイン参照、物理ピッチ、プロファイル参照、任意のケース参照、材質、照明、カメラ、背景、出力設定。
- **LegendArtwork**：共通のベクター表現からテクスチャを生成する。フォントと利用条件、余白・UV対応を固定し、日本語や記号もブラウザとBlenderで同じ字形になる経路を用意する。
- **AssetManifest**：形状・テクスチャ・HDRI・フォントの版、ハッシュ、出典、ライセンス。再配布可能なものを選ぶ。

配列のu単位とキー外形mmは区別する。物理ピッチをシーンに持たせ、mm→mの変換、上方向、前方向、回転方向をアダプターで明示する。最初のプロファイルと寸法資料は実装前に選ぶ。概形のアセットを使う場合はその旨を表示する。

## Blenderへの受け渡し

1. 選択した案をバージョン付きシーンJSONとアセット一覧へ変換する。
2. GLB形状、レジェンド画像、必要な環境アセットを同じパッケージに含める。
3. 信頼されたローカルPythonスクリプトが入力を検証し、Blenderでシーンを構築する。
4. Cycles用材質・照明・色管理を適用し、指定カメラでPNGを出力する。
5. 出力画像に対応する入力ハッシュ、Blender版、レンダー設定とログを保存する。

glTF/GLBは形状・UV・基本的なPBR材質を受け渡す候補。Three.js固有シェーダー、Blenderノード、照明・色管理が完全に往復する前提にはしない。共通の材質パラメーターから各エンジン用の材質を構築する。PBT/ABS風の粗さは視覚プリセットとして扱い、製造材質の測定値とは区別する。

ブラウザからローカルプロセスを直接実行することは想定しない。初期版はパッケージのダウンロードとCLIによるレンダー。将来のワンクリック実行には別途ローカル実行サービスかデスクトップ連携が必要となる。外部レンダーファームは当面使わない。

## 一致させるものと検証

- キーの配置・行・形状参照・文字・色指定は2D/R3F/Blenderで一致させる。
- 上面の照合用カメラで、欠落、UV反転、単位・座標軸の誤りを検出する。
- 色テクスチャと粗さ・法線などのデータテクスチャの色空間を区別する。露出・トーンマッピング・表示変換を記録し、同じ比較画面では固定する。
- フォトリアル出力はベベル、表面粗さ、接触影、レジェンドの解像度を拡大確認する。
- R3FとCyclesの陰影や色の見え方は完全一致を要求しない。同じ設定でもGPU等による差があり得るため、レンダー画像のバイト一致を保証しない。
- レンダー時は保存した案のスナップショットを使い、編集中の変更と出力元を混同しない。
- 3DやBlenderを利用できない場合も、2D編集・保存・出力を継続できるようにする。

## 色確認モード

`reference`ではキーをMeshBasicMaterial、toneMapped=false、fog=falseで描画する。環境マップ、照明、接地影は外し、色テクスチャのsRGB指定は維持する。通常の材質と色確認用材質を切り替え、元の粗さ設定を保持する。renderer全体の露出設定を書き換えないので通常照明に戻した際の状態漏れを防ぐ。

2Dのキーにあった白11%のハイライトと黒9%の下端線、ホバー時の白い面を削除。選択・ホバーは枠線で示す。キーの塗りと文字には共通データの指定色だけを使う。
