# 初期設計方針

M1〜M4.1aとKLE配列インポートを実装済み。Blenderは計画段階。変更する場合は理由とデータ互換性への影響を記録する。

## 責務の分離

`Layout + DesignStudy → 解決済みキー表現 → SVG / 3Dシーン`

- SVG → 2Dプレビュー / SVGファイル / PNG
- 3Dシーン → React Three Fiberプレビュー / PNG / Blender用レンダーパッケージ

配列の幾何情報とデザインを分離することで、同じ案を別配列へ適用できる。色・文字・キー割り当ての解決を描画方式から独立させる。2Dの画面と書き出しではSVG生成処理を共有し、3Dの形状・カメラ・照明は独立したシーン設定として扱う。詳細は[3D設計](rendering-3d.md)を参照。

| データ | 主な内容 |
| --- | --- |
| Layout | id、version、名前、keys。各キーは安定したid、機能、x/y/w/h（u単位）、将来用の回転・回転中心を持つ |
| DesignStudy | schemaVersion、id、名前、コンセプト、キーワード、対応layoutId、配色、レジェンド、Novelty参照、お気に入り、作成・更新日時 |
| Palette | base / modifier / accentなどの役割別のキー色・文字色、キー単位の上書き |
| Legend | メイン／サブ文字列、位置、フォント参照、サイズ。役割別ルールとキー単位の上書き |
| Novelty | 管理されたベクター要素、識別子、色、適用先、出典・利用条件 |

## 初期方針と理由

- **ANSI 60%から開始**：規模を抑えつつ、1u以外の修飾キーやスペースを含む描画を検証する。特殊配列への対応を急いで不正確なデータを採用しない。
- **TypeScript / React / Viteを採用**：データ型とUIの責務を分け、通常のWeb開発環境で動かす。採用バージョンはpackage-lock.jsonで固定する。
- **ブラウザ内保存**：MVPではアカウントやサーバーを不要にする。MVPは最大200案のテキストデータに絞り、localStorageを採用する。依存を増やさず保存失敗を扱えるため。保存処理は独立させ、JSONバックアップを併設する。3Dアセットを保存する段階でIndexedDBを再検討する。
- **2DはSVG、3Dは共通シーンから描画**：キー数・寸法・文字は共通データで管理する。2DのPNGはSVGから、3DのPNGはR3FまたはBlenderから出力し、描画方式と設定を区別して保存する。
- **出力とフォント**：日本語や記号を含む場合のフォールバックと配布権を確認する。テキストのままのSVGは表示環境によって字形が変わるため、プレビューの決定性と環境をまたぐ字形一致は別の検証項目とする。
- **バージョン付きデータ**：未知のバージョンを拒否し、形式変更時に移行処理を用意する。読み込み失敗で既存の案を上書きしない。
- **安全な入力**：文字列はエスケープし、任意HTMLや未検証のSVGを挿入しない。自由なSVGアップロードはMVPに含めない。

## ディレクトリ構成

```text
src/
  domain/       # 型、検証、デザインルールの解決
  renderer/     # SVG生成・PNG出力
  storage/      # 保存・復元・データ移行
  components/   # プレビューとフォーム・ダイアログ
  App.tsx       # 編集、比較、ライブラリ
```

## 必要な検証

- データ検証：不正寸法、重複ID、参照不整合、未知バージョン。
- 描画：キー数と座標、単位変換、文字のエスケープ、同じ入力の再現性。
- 保存：ラウンドトリップ、保存失敗時の表示、インポート失敗時の既存データ保持。
- ブラウザ：案を作成・複製・比較・保存・再編集し、SVG/PNGを実際に開いて確認する。

## 未決定事項

- 回転・非長方形キーの追加と、プロファイル行指定のUI。
- フォントの配布形態と、SVG書き出し時に必要な字形互換性。
- Noveltyの初期語彙・ベクターセット。
- 製造用の色指定、入稿テンプレート、外部サービス連携。いずれもMVPの成立条件にはしない。

## KLEと保存v2

`@ijprest/kle-serial`でKLEの行・属性を解釈し、取り込み前後で対応範囲を検証する。入力は厳密なJSON。原点を最小x/yに揃え、固定19.05mmピッチのLayoutに変換する。KLEのHTMLを実行せず、文字は既存のエスケープ処理を通す。

ANSI案はschemaVersion 1を維持。カスタム案はschemaVersion 2でLayoutを埋め込み、layoutIdと上書きキー参照を検証する。ライブラリv2は両方の案を含められる。localStorageはv2を優先し、存在しなければv1を読む。v2が壊れていても旧データへ黙って巻き戻さない。

比較はレイアウトIDだけでなくキーID・座標・サイズ・行・形状を含む完全な署名で判定する。カメラの距離・影・ケースは配列サイズに従う。縦長2D PNGは最大高さ8192px・1600万画素に抑える。
