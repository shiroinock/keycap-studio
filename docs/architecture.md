# 初期設計方針

以下は実装開始時の基準となる提案。実装により変更する場合は理由とデータ互換性への影響を記録する。

## 責務の分離

`Layout + DesignStudy → 解決済みキー表現 → SVG → プレビュー / SVGファイル / PNG`

配列の幾何情報とデザインを分離することで、同じ案を別配列へ適用できる。SVGを共通の描画結果にすることで、画面と書き出しのずれを減らす。

| データ | 主な内容 |
| --- | --- |
| Layout | id、version、名前、keys。各キーは安定したid、機能、x/y/w/h（u単位）、将来用の回転・回転中心を持つ |
| DesignStudy | schemaVersion、id、名前、コンセプト、キーワード、対応layoutId、配色、レジェンド、Novelty参照、お気に入り、作成・更新日時 |
| Palette | base / modifier / accentなどの役割別のキー色・文字色、キー単位の上書き |
| Legend | メイン／サブ文字列、位置、フォント参照、サイズ。役割別ルールとキー単位の上書き |
| Novelty | 管理されたベクター要素、識別子、色、適用先、出典・利用条件 |

## 初期方針と理由

- **ANSI 60%から開始**：規模を抑えつつ、1u以外の修飾キーやスペースを含む描画を検証する。特殊配列への対応を急いで不正確なデータを採用しない。
- **TypeScript / React / Viteを候補とする**：データ型とUIの責務を分け、通常のWeb開発環境で動かす。バージョンは実装開始時に確認する。
- **ブラウザ内保存**：MVPではアカウントやサーバーを不要にする。保存処理をインターフェースで分け、IndexedDBを第一候補とする。JSONバックアップを併設する。
- **SVGに統一**：キー数・寸法・文字を決定論的に扱い、生成画像特有の形状崩れを避ける。PNGは同じSVGをラスタライズする。
- **出力とフォント**：日本語や記号を含む場合のフォールバックと配布権を確認する。テキストのままのSVGは表示環境によって字形が変わるため、プレビューの決定性と環境をまたぐ字形一致は別の検証項目とする。
- **バージョン付きデータ**：未知のバージョンを拒否し、形式変更時に移行処理を用意する。読み込み失敗で既存の案を上書きしない。
- **安全な入力**：文字列はエスケープし、任意HTMLや未検証のSVGを挿入しない。自由なSVGアップロードはMVPに含めない。

## 想定するディレクトリ構成（M1以降）

```text
src/
  domain/       # 型、検証、デザインルールの解決
  layouts/      # 独立した配列データ
  renderer/     # SVG生成・PNG出力
  storage/      # 保存・復元・データ移行
  features/     # 編集、比較、ライブラリ
  samples/      # 手動サンプル案
```

## 必要な検証

- データ検証：不正寸法、重複ID、参照不整合、未知バージョン。
- 描画：キー数と座標、単位変換、文字のエスケープ、同じ入力の再現性。
- 保存：ラウンドトリップ、保存失敗時の表示、インポート失敗時の既存データ保持。
- ブラウザ：案を作成・複製・比較・保存・再編集し、SVG/PNGを実際に開いて確認する。

## 未決定事項

- 最初に追加する非ANSI配列と、その正確な資料。
- フォントの配布形態と、SVG書き出し時に必要な字形互換性。
- Noveltyの初期語彙・ベクターセット。
- 製造用の色指定、入稿テンプレート、外部サービス連携。いずれもMVPの成立条件にはしない。
